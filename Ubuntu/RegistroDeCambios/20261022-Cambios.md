## 08:43 — Rol `vscode`: ahora también actualiza

- Antes solo instalaba si no existía `/usr/bin/code`; un equipo con una versión
  vieja se quedaba con ella.
- Ahora compara la versión instalada (`dpkg-query -W code`, sin el sufijo de
  build) con la última estable que publica Microsoft en
  `https://update.code.visualstudio.com/api/update/linux-deb-x64/stable/latest`
  (`productVersion`, `url`, `sha256hash`).
  - No instalado → instala. Instalado y más viejo → actualiza. Igual o más
    nuevo → no hace nada.
  - Si la API no responde (proxy, sin red), un equipo que ya tiene VS Code
    **no se toca**; uno que no lo tiene lo instala con la URL genérica de
    siempre.
- La descarga comprueba el `sha256` que da la API.
- Instalación dentro de un `block` con `always`: aunque falle la instalación,
  se borra el `.deb`, se **restaura `/etc/apt`** y se hace `apt update`
  (antes un fallo dejaba el repo de Microsoft puesto).
- Arreglado: `cp -r /etc/apt /etc/apt.preVSCODE.bak` en una segunda ejecución
  copiaba dentro de la copia anterior (`/etc/apt.preVSCODE.bak/apt`) y la
  restauración volvía a la copia **vieja**. Ahora se borra la copia antes
  (`rm -rf` + `cp -a`).
- Las dos consultas (dpkg y API) llevan `check_mode: false` para que
  `--check` muestre la acción real.
- Probado con `--check` en el equipo de desarrollo: detecta 1.125.0 instalada,
