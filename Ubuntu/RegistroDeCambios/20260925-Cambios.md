# 2026-09-25 — Cambios

## 17:22 — `1-SetupLiveCD.sh`: apt-get queda DETENIDO al instalar zfsutils-linux (CEIABD)

**Síntoma**: en perfil CEIABD el log termina en
`Procesando disparadores para libc-bin ...` y el script no avanza (nunca aparece
`ZFS versión: ...`). La VM sigue accesible por SSH.

**Diagnóstico** (por SSH):
```
pstree -alp $(pgrep -of 1-SetupLiveCD)
  bash,5463 1-SetupLiveCD.sh
  |-apt-get,6076 install -y zfsutils-linux
  `-tee,5471 -a .../1-SetupLiveCD.sh.log
ps -eo pid,etime,stat,cmd → 6076  T+  apt-get install -y zfsutils-linux
```
`apt-get` no está colgado sino **detenido** (estado `T`) por una señal de control
de terminal: dpkg ya había terminado y apt se para al volver a tocar el tty
(stdin = terminal, stdout = pipe hacia `tee` por el `exec > >(tee ...)`).
El módulo zfs estaba cargado (`zfs 2.4.1-1ubuntu4`, `/dev/zfs` presente, `zed`
corriendo) → no es un problema de ZFS.

Contexto: esta vez `apt` **actualizó** zfsutils-linux (ya venía en el live,
2.4.1-1ubuntu5 → 2.4.1-1ubuntu5.1 de `resolute-updates`), algo que no pasaba en
las pruebas de junio.

**Desbloqueo en caliente**: `sudo kill -CONT <pid de apt-get>`.

**Fix**: `</dev/null` en los dos `apt-get` del bloque ZFS (update + install)
para que apt no tenga el terminal como stdin.

**17:26 — Verificado**: con el fix aplicado el bloque ZFS ya no se detiene y
`1-SetupLiveCD.sh` continúa normalmente. Problema **resuelto**.

## 17:31 — Mismo fallo, ahora en `2-SetupSOdesdeLiveCD.sh` (PASO 9)

**Síntoma**: con el fix anterior, `1-SetupLiveCD.sh` pasa el bloque ZFS, crea
los pools, hace el rsync y entra en el chroot. Se vuelve a parar en el PASO 9 de
`2-SetupSOdesdeLiveCD.sh` ("Instalar ZFS en el sistema instalado"), justo tras
`Procesando disparadores para libc-bin`, al final del `apt-get install` de ZFS.

**Causa**: la misma. El script 2 se lanza con
`chroot /mnt ... 2>&1 | tee ...` y hereda el terminal como stdin, así que sus
`apt-get` (líneas ~428, ~468, ~1039, ~1050) pueden quedar detenidos igual.

**Fix** (un solo punto en vez de parchear cada apt-get): en `1-SetupLiveCD.sh`,
la llamada al chroot pasa a
`chroot /mnt "$SCRIPT2" </dev/null 2>&1 | tee ...`.
Comprobado antes de aplicarlo que el script 2 no lee nada del teclado (todos sus
`read` leen de pipes o ficheros).

**Pendiente**: confirmar en la próxima ISO que el script 2 completa el PASO 9 y
llega a `Correcto`.
