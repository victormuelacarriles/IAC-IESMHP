# Cambios 2026-10-05

## 13:01 — Rol `vmware`: no abortar si falla la compilación de módulos

- `Ubuntu/ansible/roles/vmware/tasks/main.yml`, tarea
  «Ejecutar post-instalación de VMware(2/2) (compilación)»
  (`vmware-modconfig --console --install-all`): añadido `ignore_errors: true`.
  Si la compilación de los módulos de kernel falla, Ansible lo marca como
  error ignorado y el rol continúa en lugar de detenerse.

## 13:10 — Rol `vmware`: compilación sin pantalla con `xvfb-run`

  (`/tmp/vmware-root/*.log`) termina en `Use library directory` → aborta al

## 13:08 — roles.yaml: `--tags <rol>` no ejecutaba nada

- **Síntoma**: `ansible-playbook ... roles.yaml --tags "vmware"` no ejecutaba ninguna tarea.
- **Causa**: los roles estaban listados como `- vmware` (sin tags). Ansible no asigna
  automáticamente el nombre del rol como tag, así que ninguna tarea casaba con `vmware`.
- **Fix** (`Ubuntu/ansible/roles.yaml`): cada rol pasa a `- { role: X, tags: X }` y el
  pre_task `apt update_cache` lleva `tags: always` (se ejecuta también con `--tags`).
- Ojo: los tags distinguen mayúsculas (`--tags Docker`, `--tags preparaAD`, `--tags horaHTTP`).
  Los tags internos que ya existían (`docker`, `rootless`, `preparaad`, `ad`, `sftp`) siguen valiendo.

## 13:14 — Rol `vmware`: `vmware-modconfig` rc=2 + comprobación final real

- Prueba en SMRD-00 (VMware 26.0.1, reinstalado desde cero): con `xvfb-run` ya no
  falla por pantalla, pero `vmware-modconfig --console --install-all` sale con **rc=2**
  en 0,34 s sin stdout. El stderr solo trae el aviso de libaio, que **no es la causa**.
  Pendiente ver el motivo real en `/tmp/vmware-root/*.log`.

  AppLoader busca `libaio.so.1`, así que el aviso seguía saliendo.
- Cambios en `Ubuntu/ansible/roles/vmware/tasks/main.yml`:
  - Enlace `/usr/lib/x86_64-linux-gnu/libaio.so.1 -> libaio.so.1t64` (quita el aviso).
  - Nueva comprobación `modinfo -k <kernel> vmmon/vmnet`: también se compila si faltan
    los módulos para el kernel actual (antes, con VMware ya instalado, nunca se recompilaba
    tras un upgrade de kernel).
  - Si `vmware-modconfig` falla, se muestran las últimas 40 líneas de su log.
  - Comprobación final: `modprobe vmmon/vmnet` + `lsmod` + `mokutil --sb-state` → mensaje
    OK/ERROR (no aborta el playbook).
